# 통합 연구계획·보고서 에이전트

설계 버전 **1.4**. 연구아이디어를 질문과 토론으로 구체화하고, 실제 자료가 확보되면 연구보고서를 작성·검토하는 범용 지침입니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| [AGENTS.md](./AGENTS.md) | 공통 원칙, 실행 모드, 파일 인계, 검수 상한, 완료 조건 |
| [coordinator.md](./coordinator.md) | 연구별 경로·자료·연결표 관리, 승인과 작업 상태 관리 |
| [writer.md](./writer.md) | 연구자 당사자 시점의 계획서·보고서 집필 |
| [independent-reviewer.md](./independent-reviewer.md) | 원자료 대조, 반려·재검토 기록, 동작 검증 사례 |
| [editor.md](./editor.md) | 문체·표·도식·분량 편집, 모드별 전달용 원고 생성 |

AGENTS.md만으로 상세 절차가 모두 제공되지는 않습니다. 저장소 파일 전체를 사용하거나, AGENTS.md와 총괄 지침 및 수행할 역할 파일을 함께 AI에 제공합니다.
역할 파일은 자동으로 여러 에이전트를 실행하는 프로그램이 아닙니다. 한 AI가 순차적으로 역할을 수행할 수 있으며 실제 검수 방식을 밝혀야 합니다.

## 사용 방법

1. 연구명과 계획/보고서 모드, 요청 범위를 정합니다. 특정 주제나 수치를 지침에 고정하지 않습니다.
2. 적용 규정과 비식별 자료를 로컬에서 제공합니다. 총괄은 `projects/<연구명>/`에 자료 대장·연결표·상태를 정리합니다.
3. 집필은 같은 폴더의 `draft.md`를 쓰고 검수는 `review-notes.md`에 판정을 남깁니다.
4. 반려 후 재작성·재검수는 최대 2회입니다. 미해결 시 중단하고 연구자의 자료 보완·범위 조정·보류 결정을 받습니다.
5. 편집은 계획 모드의 `research-proposal.md` 또는 보고서 모드의 `research-report.md`를 같은 연구 폴더에 생성합니다.
6. 실제 편집본과 미확인 항목까지 확인한 범위에 맞춰 완료 상태를 보고합니다.

`<연구명>`은 실제 고유 폴더명으로 바꾸는 변수입니다. 연구가 바뀌면 다른 폴더를 사용합니다. 승인 기록 없이 검수 회차를 초기화하지 않습니다.

### 시작 요청 예시

```text
AGENTS.md와 총괄·집필·독립검수·편집 지침을 적용해 주세요.
이번 연구명은 [연구명], 요청 범위는 [계획서/보고서/부분 수정]입니다.
제공한 자료의 상태를 확인하고 목적별 연결표를 먼저 작성해 주세요.
예상 결과나 미확인 판단을 사실로 쓰지 마세요.
산출물과 검토 기록은 projects/<연구명>/에 분리해 주세요.
```

## 설계 검증

[독립검수 지침](./independent-reviewer.md)의 동작 검증 사례에 실제 응답한 뒤 필수 행동·실패 기준과 대조합니다. 주제가 바뀔 때 자료가 섞이지 않는지, 재검수 2회 후 멈추는지, 연구자 승인 없이는 재개하지 않는지도 확인합니다.
지침 파일의 구조 점검은 실제 AI 실행 성능 검증과 다릅니다. 수행하지 않은 테스트를 통과했다고 말하지 않습니다.

## 공개 범위

이 저장소에는 범용 지침과 사용 안내만 둡니다. `projects/`는 기본적으로 Git 추적에서 제외됩니다. 실제 학생·참여자 자료, 내부 문서, 가명 대응표, 인증정보를 올리지 않습니다.
최종 제출·공개는 연구자가 자료와 규정을 확인하여 결정합니다. 연구자 승인만으로 근거 없는 내용을 사실로 확정할 수는 없습니다.

변경 내역은 [CHANGELOG.md](./CHANGELOG.md)와 Git 커밋 기록에서 확인할 수 있습니다.
